## Codebase Patterns
- Add a tiny compile-time anchor file (for example, `tui/deps.go`) when introducing migration dependencies before feature code exists; this keeps modules in `go.mod` after `go mod tidy`.
- For Bubble Tea migration work, keep state transitions in `tui/app.go` and keep rendering logic split across `tui/views.go` + `tui/components.go` to avoid another monolithic UI file.
- Keep reusable color tokens and lipgloss theme definitions in `tui/styles`; view/component code should consume styles through the model-owned theme instead of creating ad-hoc styles.
- Keep keyboard hints generated from `key.Binding` metadata (`Binding.Help()`) so help text stays in sync with keymap changes.
- For async loading screens, gate `spinner.TickMsg` handling by current view-state and re-enter loading with `tea.Batch(spinner.Tick, loadCmd)` so the spinner runs only while that screen is active.
- Use `Program.Run()` (not deprecated `Program.Start()`) when launching Bubble Tea programs from `main.go`.
