## Codebase Patterns
- Add a tiny compile-time anchor file (for example, `tui/deps.go`) when introducing migration dependencies before feature code exists; this keeps modules in `go.mod` after `go mod tidy`.
- For Bubble Tea migration work, keep state transitions in `tui/app.go` and keep rendering logic split across `tui/views.go` + `tui/components.go` to avoid another monolithic UI file.
- Keep reusable color tokens and lipgloss theme definitions in `tui/styles`; view/component code should consume styles through the model-owned theme instead of creating ad-hoc styles.
- Keep keyboard hints generated from `key.Binding` metadata (`Binding.Help()`) so help text stays in sync with keymap changes.
- For async loading screens, gate `spinner.TickMsg` handling by current view-state and re-enter loading with `tea.Batch(spinner.Tick, loadCmd)` so the spinner runs only while that screen is active.
- For async Bubble Tea data commands, include a request ID in every success/error `tea.Msg` and process the message only when the model is still in the expected state with the matching pending request ID.
- Use `Program.Run()` (not deprecated `Program.Start()`) when launching Bubble Tea programs from `main.go`.
- For keyboard-heavy Bubble Tea views, route global keys first and then dispatch to per-state key handlers; this keeps transitions explicit and prevents conflicting key behavior across screens.
- Route every view change through a shared transition validator (`transitionTo` + `validateStateTransition`) and drop into `viewStateError` on invalid transitions so impossible navigation paths cannot leak into rendering.
- For Bubble Tea forms, treat the submit action as a virtual focus target at index `len(fields)` so `tab`/`shift+tab` navigation and explicit `enter` submission stay predictable.
- When supporting optional DynamoDB index queries, only set `QueryInput.IndexName` when the form value is non-empty to preserve base-table query behavior.
- For paginated Bubble Tea tables, keep selection as an absolute row index and derive the visible page from `selected/pageSize`; this keeps resize and page-jump behavior deterministic.
- When rendering result detail + JSON modal, keep both display-safe rows (`result.Items`) and typed raw payloads (`result.RawItems`) in model state so table readability and raw inspection can evolve independently.
